# Демо-сценарии для защиты

Проверка обязательных возможностей кейса (распознавание сленга, расшифровка из словаря, использование в ответе, работа с опечатками). Все запросы выполняются через `POST /chat`.

> Как прогнать: `docker compose up --build`, затем каждый сценарий ниже через `curl` или Swagger UI `http://localhost:8000/docs`.

---

## 1. Сленг + правильное использование расшифровки в ответе

**Запрос:**
```bash
curl -X POST http://localhost:8000/chat -H "Content-Type: application/json" \
  -d '{"query": "Какие показатели учитываются в отчёте по ГПНР?"}'
```

**Что проверяем:**
- `resolved_terms` содержит `{"original": "ГПНР", "canonical": "Газпромнефть-Развитие", ...}`;
- в тексте `answer` расшифровка «Газпромнефть-Развитие» употреблена, а не только сокращение;
- указан `[Источник: ...]`.

---

## 2. Опечатка в аббревиатуре (fuzzy-матчинг)

**Запрос:**
```bash
curl -X POST http://localhost:8000/chat -H "Content-Type: application/json" \
  -d '{"query": "IT-технологии и КПЕ по ремонту скважин"}'
```

**Что проверяем:**
- введённая опечатка `КПЕ` распознана как `КПЭ` → «Ключевые показатели эффективности»;
- системой ассистент отвечает релевантно, а не «не понимаю запрос».

> Демо-приём: показать один запрос с нарочно искажённой аббревиатурой — это точь-в-точь сценарий «нестандартное написание» из кейса.

---

## 3. Отраслевая аббревиатура из словаря

**Запрос:**
```bash
curl -X POST http://localhost:8000/chat -H "Content-Type: application/json" \
  -d '{"query": "Что такое ГРП и как ПНГ влияет на экологию?"}'
```

**Что проверяем:**
- `resolved_terms`: `ГРП → Гидроразрыв пласта`, `ПНГ → Попутный нефтяной газ`;
- ответ использует обе расшифровки и ссылается на базу знаний.

---

## 4. Гибридный поиск по базе знаний

**Запрос:**
```bash
curl -X POST http://localhost:8000/chat -H "Content-Type: application/json" \
  -d '{"query": "Что такое RAG и зачем он нужен?"}'
```

**Что проверяем:**
- ассистент вызывает инструмент `search_article` (вызов поиска логируется, `raw_context` не пуст);
- `sources` содержит файл-источник, в ответе указан `[Источник: ...]`;
- на многоаспектный вопрос агент может вызвать `search_article` несколько раз с разными подзапросами (multi-hop), источники при этом суммируются.

---

## 5. Регламентированный отказ (нет данных в базе)

**Запрос:**
```bash
curl -X POST http://localhost:8000/chat -H "Content-Type: application/json" \
  -d '{"query": "Какой курс акций Газпром нефти завтра?"}'
```

**Что проверяем:**
- ответ: «В корпоративной базе знаний отсутствует информация по данному запросу»;
- ассистент **не галлюцинирует** (требование system-промта, `agent.py`).

---

## 6. Мульти-терная сессия

```bash
# 1-й ход — сохраняем session_id из ответа
curl -X POST http://localhost:8000/chat -H "Content-Type: application/json" \
  -d '{"query": "Что такое KPI нефтяной компании?"}'

# 2-й ход — переиспользуем session_id
curl -X POST http://localhost:8000/chat -H "Content-Type: application/json" \
  -d '{"query": "Разверни подробнее?","session_id": "<session_id>"}'
```

**Что проверяем:**
- диалог помнит контекст (`GET /history/<session_id>` показывает оба хода).

---

## 7. Статус сервиса

```bash
curl http://localhost:8000/health
```

**Ожидаем:**
```json
{"status": "ok", "ollama_status": "up", "db_status": "ready", "models_ready": true, "message": "Ready for tests"}
```

Если сервис ещё загружает модели/индекс:
```json
{"status": "degraded", "ollama_status": "up", "db_status": "not_ready", "models_ready": false, "message": "Initializing..."}
```

Проверять и в Docker (Ollama в отдельном контейнере, адрес берётся из `OLLAMA_HOST`).
